# T-M1-02 Approval requirement logic
Milestone: M1 · Depends on: T-M1-01 · FRD: main rules 2, 3, 6

## Goal
Decide whether a change needs approval and what kind.

## In scope / out of scope
In: strict mode on/off check, weaker change detection, one-approval-per-change rule.
Out: TOTP validation (T-M1-05), 24-hour wait (T-M1-07).

## Files likely touched
lib/policy/approval.dart (+ tests)

## Acceptance checks
- [ ] Stricter change never needs approval
- [ ] Weaker change with strict mode off: no approval needed
- [ ] Weaker change with strict mode on: approval needed
- [ ] Each approval covers exactly one change
- [ ] After approval is used, the next weaker change needs a new approval
